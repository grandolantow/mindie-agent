## 3. Verified Core Capabilities

1. **Native Installation & 24-Hour Silent Compatible Updates**:
   - First-time installation pins the immutable `v0.0.1` tag; more than 24 hours after the last successful check, routine use asynchronously selects the highest compatible ordinary Release, builds the locked `uv` environment in the background, and switches atomically when idle while preserving existing consent.
2. **Remote Ascend Execution & Local Experience Loop**:
   - All six environments completed real remote SSH operations via `remote-dev`, deterministic public dialogue extraction, Gitleaks + privacy-rule redaction, small-model navigation indexing, and local hybrid search verification.
3. **Public Contribution, Bot Review & Incremental Sync**:
   - Verified end-to-end public PR creation, Grok Bot safety review and merge into [`knowledge-vllm-ascend`](https://github.com/mindie-agent/knowledge-vllm-ascend), incremental client sync (661 task packages), and `helpful` feedback submission.
4. **Bounded Local Diagnostics & Opt-In Issue Reporting**:
   - Verified bounded local structured log rotation, cross-task fault fingerprint deduplication, and opt-in GitHub Issue fault reporting.
5. **Kimi Code Native Integration & Acceptance-Driven Fixes**:
   - On kimi CLI `2.1.1` and `2.2.0`, verified dual-shape identity verification for the unified entry (both top-level and nested skill activations bind; plain text, headless, and foreign same-named skills are always refused), the full port to the `knowledge v0.11.0` summary-worker protocol (`--identity` fingerprinted handshake plus a strict outcome envelope — no fallback summary and no replay of uncertain paid calls), and second-level background atomic updates built with `uv`.
   - Acceptance-driven fixes merged: the updater build timeout moved to the `uv` path with an honest `deadline` class, consent/community authority pinned to the profile instead of forking per generation, systemd stale-receipt retirement with SIGTERM terminal receipts (knowledge v0.11.1), bounded outbox retries with visible settle, the Windows sharing-violation retry, the `uv venv` fallback for stock Ubuntu, and `service_launch_context` carrying the summary worker's native binary across service-manager PATHs.
6. **DeepSeek Harness Native Integration (Addendum Acceptance)**:
   - On macOS 27.0.1 arm64 + DSH `0.2.0-rc.2`, verified the Host-row composition (no shipped row or preset override), `/mindie-agent` skill discovery and model-hiding policy, real MCP calls for `knowledge_query` / `knowledge_explain` / `knowledge_sync`, and registration plus visible failure behavior of the official `remote-dev` MCP tools.

## 4. Known Limitations in `0.0.1`

- **OpenAI Codex CLI Child-Agent (`spawn_agent`) Interruption**:
  - When OpenAI Codex CLI interrupts a child agent (`spawn_agent`), Codex currently aborts the waiting handle without delivering a cancellation signal to an in-flight MCP tool call inside the child agent, which can leave a local helper/SSH subprocess or one-shot remote command running until completion (main-thread tool cancellation in Codex and standard cancellation in Claude Code work as expected).
  - MindIE Agent documents this upstream host limitation transparently rather than adding intrusive process-hunting watchers or arbitrary business timeouts. Persistent background jobs remain explicitly controllable via `remote-dev` (`job_cancel`). We have shared a minimal reproduction and fix analysis upstream at [openai/codex#26956](https://github.com/openai/codex/issues/26956#issuecomment-6205886409).
- **Kimi Code Host Interaction Boundary**:
  - Headless `kimi -p` and the ACP channel produce no native slash origins; mutation operations (`sharing-*`, `deactivate`, `recover`, `reporting-*`) are reachable only in the TUI (`/mindie-agent:<op>` or a bound session). Kimi's prompt mode reports no usage counters, so every paid summary call is accounted as `model_calls=1` with `usage_known=false`, never as zero. On GBK-codepage hosts the ACP stream renders CJK text as mojibake (the persisted `wire.jsonl` is unaffected, so capture is intact).
  - On Linux/WSL the background update schedule is honestly reported as manual (no task registration); Linux services require a `systemd >= 254` user manager. On macOS the first on-demand service start after a background flip can transiently report `unknown` (surfaced honestly); the next on-demand call recovers, with captures and data unaffected.
- **Benchmark Scope**:
  - End-to-end business quality and efficiency benchmarks are tracked separately; `0.0.1` makes no premature quantitative speedup claims.
- **DSH `0.0.1` Scope Limits**:
  - Read-only knowledge plus `remote-dev` only; no Stop capture, experience contribution, usefulness feedback, fault reporting, or per-session knowledge identity; `remote-dev` state is Host-level and shared; only macOS was accepted, and Windows / Linux and real remote NPU execution remain unverified.
