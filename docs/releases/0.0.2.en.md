# MindIE Agent `0.0.2` Release Notes

[中文](https://github.com/mindie-agent/mindie-agent/blob/v0.0.2/docs/releases/0.0.2.md) · [Documentation Center](https://github.com/mindie-agent/mindie-agent/blob/v0.0.2/docs/README.en.md)

This document summarizes the key changes, component source manifest, benchmark results, and usage notes for MindIE Agent `0.0.2`.

In `0.0.2`, the main product and all four host plugins—OpenAI Codex CLI, Claude Code, Kimi Code, and DeepSeek Harness (DSH)—align on version `0.0.2`, while shared runtime packages and `mindie-bench` (`0.3.0`) maintain their own version sequences. This release unifies the community contribution and fault-reporting switch, tightens cross-component runtime boundaries, locks dependency installation, and delivers real-task and component benchmark results.

---

## 1. Key Changes

- **Unified Contribution & Fault-Reporting Switch**: Community knowledge sharing and automatic tool fault reporting now share a single contribution switch (`mindie-consent.json`, off by default). Explicitly enabling it configures knowledge sharing and starts the native background reporter service; disabling it immediately stops outgoing sends on both paths while keeping local diagnostic logs and remote development tools active. Pending fault records are preserved across temporary network or GitHub authentication failures.
- **Remote Development & Multi-Agent Coordination**:
  - `remote-dev` enforces independent timeout budgets across persistent background job controls, RPC handshakes, and multi-stage SSH diagnostics, preserving completed remote command outputs while explicitly distinguishing execution failures from uncertain external writes (`unknown`).
  - `coordinator` arbitrates NPU device and port leases across concurrent Agents and resolves the current Git commit directly on task submission instead of reading cached metadata.
- **Host Plugin Experience & Cross-Platform Stability**:
  - **Claude Code**: Streamlines first-time cold-start initialization so ready MCP servers no longer wait on the exclusive lock of optional feed synchronization;
  - **OpenAI Codex CLI**: Shortens virtual-environment directory identifiers under default Windows user paths to stay within traditional Windows path limits;
  - **Kimi Code CLI**: Supports formal Release compatibility filtering and atomic upgrade cutover (native Windows requires Python 3.12+, preferring 3.13);
  - **DeepSeek Harness (DSH)**: Installs the summary worker in persistent application data storage so removing temporary setup directories does not affect background indexing, and drains child process trees on setup timeout;
  - **Shared Runtime Consolidation**: Removes duplicated diagnostic fallback and consent bootstrap copies from host plugins in favor of the pinned shared runtime packages.

## 3. Benchmark Results and `0.0.3` Roadmap

Full experiment definitions and per-run records are available in the [`0.0.2` benchmark report (`value-results.md`)](https://github.com/mindie-agent/mindie-agent/blob/v0.0.2/docs/releases/0.0.2/value-results.md).

### 1. Measured Gains from `remote-dev` and `coordinator`

- **`remote-dev` (`v0.10.1`, Remote Ascend Container Execution Substrate)**:
  - On the `vLLM-Ascend` quantization repair task (`quarot`, 3 repetitions), adding `remote-dev` **solved `3/3` runs and reduced 3-run total delivery time from `747.31s` to `550.89s` (paired solved-run time `564.39s → 550.89s`, a `1.025x` speedup)**;
  - On the dual-device troubleshooting task (`dp2`), it matched baseline solve rate and delivery time (`0.963x`) while turning cross-host SSH, container file I/O, patching, and persistent background jobs into structured tool calls.
- **`coordinator` (`v0.5.3`, Multi-Agent Lease & Port/Device Arbitration)**:
  - Across 3 two-agent contention runs, the uncoordinated check-then-bind baseline established only `3` active listeners while suffering `3` port conflicts and `3` duplicate device selections;
  - With `coordinator`'s lease queue, **active listeners doubled from `3` to `6` (`3 → 6`), port conflicts dropped to `0` (`3 → 0`), and duplicate device selections dropped to `0` (`3 → 0`)**, with the waiting agent acquiring the released lease in ~`2ms`.

### 2. `npu-top` and `diagnostics` Component Verification

- **`npu-top` (`v0.1.9`)**: Supports live hardware probing across both idle and busy Ascend A2 (910B single-Die) and A3 (910C dual-Die `Phy-ID`) hosts; across 3 hardware-capture and live container runs, all `24` physical devices, `16/16` process mappings, and `3/3` container ownership checks passed.
- **`diagnostics` (`v0.4.3`)**: Provides cross-platform background fault deduplication (macOS `launchd` / Windows `Task Scheduler`) and allowlist-only redaction (uploading only component version, commit SHA, and allowlisted execution metadata—never transcripts, command arguments, or local paths); across 3 reporting runs, `9` controlled faults were deduplicated into `3` reports with `3/3` passes on field retention, privacy redaction, and immediate stop upon consent withdrawal.

### 3. Knowledge System (`knowledge` + Skills) and `0.0.3` Optimization Plan

- **Task Completion and Cross-Task Experience Reuse**:
  - Enabling `knowledge` retrieval and shipped Skills increased completed tasks from `2/3` to **`3/3`** on both `dp2` (Codex) and `dsh`;
  - In cross-task experience transfer (1 seed task with capture followed by 2 distinct evaluation tasks, repeated 3 times), later evaluation tasks hit and read the captured seed experience in **`5/6`** runs, matching baseline evaluation speed (`1.011x` ratio, `6/6` pairs solved).
- **Planned `0.0.3` Optimization**:
  - Because current retrieval and long-context reading add extra interaction turns and token overhead, single-task delivery time is still slower than the no-retrieval baseline (`0.595x–0.975x`).
  - **In `0.0.3`, we plan to optimize `knowledge` retrieval gating and context conciseness** to reduce per-task and end-to-end latency while keeping the gains in solve rate and cross-task reuse.

## 4. DSH `0.0.2` Same-Version Refresh Notice

To align product versions, `mindie-agent-dsh` remains at version `0.0.2`, replacing the earlier `0.0.2` tag (`828c375d1f546ed653250526465b8075c1691390`) with the exact commit listed in the component table above.

- **Upgrade Note**: Because the legacy updater only selects versions strictly greater than the installed version, **existing installations of the earlier DSH `0.0.2` (`828c375...`) will not automatically pull the refreshed build**.
- **Required Action**: Users on the earlier `0.0.2` build should run a one-time explicit refresh of the shared runtime (`setup.py`) and DSH plugin bundle per [`same-version-refresh.md`](https://github.com/mindie-agent/mindie-agent-dsh/blob/main/docs/same-version-refresh.md) and **restart the entire DSH process**. Existing user consent and local knowledge data are preserved.

## 5. Usage Notes

- **Contribution Switch Defaults on Upgrade**: Existing `disabled`, `later`, or `read-only` configurations—as well as legacy knowledge-only `contribute` records created before the unified switch—remain off for fault reporting after upgrading to `0.0.2` until explicitly enabled through the unified contribution switch.
- **Windows Privilege Consistency**: On Windows, run the host CLI and background scheduled tasks under the same ordinary desktop user account; running the host CLI with Administrator elevation may create state directories unreadable by an ordinary-user scheduled task. If enterprise application control policies block `pythonw.exe`, background capture and reporting will not start, while foreground MCP tools remain unaffected.
