# MindIE Agent `0.0.2` Release Notes

[中文](https://github.com/mindie-agent/mindie-agent/blob/v0.0.2/docs/releases/0.0.2.md) · [Documentation Center](https://github.com/mindie-agent/mindie-agent/blob/v0.0.2/docs/README.en.md)

This document records the changes, exact component source manifest, tiered verification evidence, ten-repository benchmarks, and known boundaries for MindIE Agent `0.0.2`. Published packages and reports are available from each repository's GitHub Release.

In `0.0.2`, the main product and the four host plugins—OpenAI Codex CLI, Claude Code, Kimi Code, and DeepSeek Harness (DSH)—align on version `0.0.2`. Shared runtime components and the benchmark runner `mindie-bench` (`0.2.0`) maintain independent version sequences. This release focuses on cross-component correctness after the codebase simplification, a unified contribution and fault-reporting consent boundary, locked dependency installation, and reproducible benchmarks shipped with every release.

---

## 1. Key Changes

- **Unified Contribution & Fault-Reporting Switch**: Community knowledge sharing and automatic tool fault reporting now share a single contribution switch governed by `mindie-consent.json` in the installation profile. Explicitly enabling contribution configures knowledge sharing and provisions the native background reporter service; disabling it immediately stops outgoing sends on both paths while keeping local diagnostic logs and remote development tools active. This release also fixes the DSH reporting configuration path mismatch and retains pending fault records across temporary GitHub network or authentication failures rather than dropping them after transient lookup errors.
- **Remote Execution & Cluster Coordination**: Persistent job controls, RPC handshakes, and multi-stage SSH diagnostics in `remote-dev` operate under bounded, non-overlapping timeout budgets. Task submissions in `coordinator` resolve the current Git commit directly instead of reading cached source metadata. Completed remote execution outputs are preserved even if local bookkeeping times out, and failures remain explicitly separated from uncertain external writes (`unknown`).
- **Knowledge Loop & Consent Safety**: Fixes cover consent migration, Windows DPAPI context protection, and concurrent consent updates, while retaining prior fixes for background service ownership, task retirement, and Git credential resolution.
- **Host Process Boundaries & Cold Start**:
  - **Claude Code**: Serializes first-time cold-start state initialization so ready MCP servers no longer wait on the exclusive lock of optional feed synchronization; maintenance timeouts report `maintenance incomplete` explicitly while connected MCP tools remain available.
  - **OpenAI Codex CLI**: Shortens runtime directory identifiers under the default Windows user layout (while keeping the full identity in the installation receipt) so dependency paths stay within traditional Windows path limits.
  - **Kimi Code CLI**: Requires Python 3.12+ on native Windows (preferring 3.13 during setup) and uses the shared release selector to verify formal Releases, host SemVer compatibility, and exact tag commits.
  - **DeepSeek Harness (DSH)**: Installs the summary worker inside persistent application data storage so removing the temporary setup checkout does not break background indexing; drains the full process tree on setup timeout, reports missing token usage as unknown, and removes error-masking retry paths that deleted configuration files.
- **Shared Runtime Ownership**: Removes duplicated diagnostic fallback modules and consent bootstrap copies from the plugins in favor of the pinned shared runtime packages. Shared runtime errors surface directly without altering saved user consent or overwriting primary business outputs.
- **Linux Benchmark Sandbox**: `mindie-bench` supports `uv`-managed interpreter aliases pointing to the authorized Python runtime while isolating unauthorized files and host loopback traffic; native Unix gateway tests exercise the real relay path.

### Verification Highlights

- **`npu-top 0.1.9` Idle-Host Live Probe Contract Fix**: During live A3 verification, standing host `.154` was idle (confirmed directly via `npu-smi`). The legacy `0.1.8` live test asserted at least one busy device and process, causing 2 passes and 1 failure on the first run. Rather than starting artificial workloads to satisfy the test, `npu-top v0.1.9` (`9bbf6de590b12fe1109040e0ef86817bd2c5f3e0`) updates the live probe contract to verify snapshot consistency, A3 dual-Die (`Phy-ID`) mapping, and busy-count aggregation regardless of whether the host is idle or busy; all 3 live tests then passed. The published `v0.1.8` (`36ae994`) release remains archived as-is.
- **Native Windows & Long-Path Verification**: On an independent Windows test machine under an ordinary desktop token (`TokenElevation=0`), the production `pythonw.exe` and Task Scheduler pipeline completed Stop replay, deterministic redaction, and block organization in ~6.5 seconds without model calls. A Codex layout matching the default Windows user path length verified real dependency installation, imports of the longest Anthropic and LangSmith modules, and receipt reuse across repeated startups. Claude Code initialized a fresh native Windows profile in 46.077 seconds with both MCP servers connecting in 17.328s and 23.208s (within the 30s host budget); optional feed sync timed out at its 20s budget and recorded `maintenance incomplete` while keeping connected tools available.
- **Kimi Native Update & Compatibility Filtering**: Kimi `2.2.0` on macOS completed a native `0.0.1 -> 0.0.2` upgrade in an isolated profile against a controlled local release catalog (verifying pinned source fetch, runtime build, native API installation/readback, atomic cutover, and idempotent re-check). Windows Kimi `2.1.1` and macOS `2.2.0` separately verified SemVer compatibility filtering and non-downgrade behavior against the official catalog.

The earlier Windows/WSL capture tests used `knowledge b2c59a7`; the Claude Code cold-start test used `knowledge 8d9eab1`. These runs are not complete reinstall tests of the final dependency set. Native consent and reporting tests of the final combination are recorded below.

### Unified Contribution Switch & Real Fault Reporting Evidence

1. **Strict Separation of Three States**: MindIE Agent keeps **configuration written** (`mindie-consent.json` saved), **background worker running** (native OS service active), and **external publication completed** (GitHub Issue or PR created) strictly distinct. Missing authentication, network errors, or service startup failures surface explicitly and never appear as successful delivery.
2. **Upgrade Consent Boundary**: Existing `disabled`, `later`, and `read-only` configurations remain off across upgrades. Legacy knowledge-only `contribute` records lacking the unified consent revision do **not** silently gain fault-reporting permission on upgrade; users opt in explicitly once through the unified contribution entry. Disabling the switch immediately stops subsequent outgoing sends for both paths without revoking already-published public records.
3. **Cross-Platform Native Reporter & Deduplication Proof**:
   - In an isolated macOS profile with non-editable installs of `knowledge` (`4e32830`) and `diagnostics` (`1b5a0ee`), explicitly enabling the unified switch started the native macOS `launchd` reporter, which automatically created public synthetic [Issue #243](https://github.com/mindie-agent/mindie-agent/issues/243). Readback confirmed that the Issue contained `diagnostics 0.4.3`, the full commit SHA, and allowlisted metadata only—excluding private sentinels, raw error strings, and local paths. A duplicate fault was deduplicated by the same worker, leaving a single published incident in the durable queue.
   - On Windows (RTX 4090, ordinary desktop token `TokenElevation=0`), the Task Scheduler worker running the exact same installed commits consumed the matching synthetic fault and reconciled it via read-only GitHub lookup to [Issue #243](https://github.com/mindie-agent/mindie-agent/issues/243) without creating a duplicate Issue.
   - Following verification, test [Issue #243](https://github.com/mindie-agent/mindie-agent/issues/243) was closed and the isolated background service was removed.

### What These Benchmarks Prove and Do Not Prove

- **What they prove**: On fixed public synthetic inputs in a clean build environment, each component's core CPU operation (redaction, technical tokenization, patch/protocol normalization, multi-role placement, `npu-smi` parsing, host transcript projection, and retrieval scoring) produces the expected output and establishes a reproducible per-operation latency baseline (`us/op`) tied to the exact tagged commit.
- **What they do not prove**: CPU microbenchmarks do not measure SSH transport latency, container startup, or live Ascend NPU kernel execution. They **do not** replace live A2/A3 NPU integration tests, and they **must not** be combined with pytest wall times, download counts, or parser latencies to claim NPU throughput gains or end-to-end Agent productivity percentages. End-to-end engineering productivity requires controlled task comparisons.

## 5. DSH `0.0.2` Same-Version Refresh Notice

By product decision, `mindie-agent-dsh` remains at version `0.0.2` as a one-time authorized replacement of the earlier `0.0.2` tag (`828c375d1f546ed653250526465b8075c1691390`). The paired source commit for this release is listed in the component table above and in [`benchmark-manifest.json`](https://github.com/mindie-agent/mindie-agent/blob/v0.0.2/docs/releases/0.0.2/benchmark-manifest.json).

- **Upgrade Boundary (Important)**: Because the legacy updater only selects versions strictly greater than the currently installed version, **existing installations of the earlier DSH `0.0.2` (`828c375...`) will not automatically update to the refreshed `0.0.2`**.
- **Required Action**: Users who installed the earlier `0.0.2` must perform a one-time explicit refresh of both the shared runtime (`setup.py`) and the DSH plugin bundle using the exact source SHA per [`same-version-refresh.md`](https://github.com/mindie-agent/mindie-agent-dsh/blob/main/docs/same-version-refresh.md), then **restart the entire DSH process** (bypassing client caches for the unchanged tag name). Existing consent and local knowledge data are preserved. Future higher versions will update through the standard channel.

## 6. Known Boundaries

- **Machine-Specific Windows Application Control Policy**: On the Lenovo Windows acceptance machine, OS application control blocked `pythonw.exe` (`WinError 4551`). Machine security policy was neither modified nor bypassed, and background capture on that host is not counted as passed.
- **Windows Token Elevation Boundary**: Background capture and reporting are verified under ordinary desktop tokens (`TokenElevation=0`). Running a host CLI with administrator elevation may create private state directories unreadable by an ordinary-user scheduled task; mixed elevated-host and ordinary-task execution is not declared supported, and MindIE Agent does not alter Win32 ACLs or elevate background tasks to bypass this boundary.
- **Distinct Evidence Scopes**: Source contract suites, partial native host loops, live A2/A3 NPU integration runs, and CPU microbenchmarks establish separate facts. Historical `0.0.1` host matrix results are not carried over as fresh `0.0.2` acceptance evidence.
