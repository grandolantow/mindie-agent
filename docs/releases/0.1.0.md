[English](0.1.0.en.md) · [文档中心](../README.md) · [版本兼容与无感更新](../release-compatibility-and-update.md)

**`v0.1.0` 是 MindIE Agent 的首个正式里程碑版本（First Official Milestone Release）。**

本版本完整汇总并固化了 MindIE Agent 从早期内测预览版（[`0.0.1`](0.0.1.md) $\to$ [`0.0.2`](0.0.2.md) $\to$ [`0.0.3`](0.0.3.md)）到生产级昇腾（Ascend NPU）AI Infra 智能研发底座的全部架构演进与工程能力：全面适配 **4 大原生编码宿主客户端**（`Claude Code`、`OpenAI Codex CLI`、`Kimi Code CLI`、`DeepSeek Harness`），交付 **7 大共享运行时与性能分析/建模组件**（`remote-dev`、`knowledge`、`diagnostics`、`coordinator`、`npu-top`、`profiler`、`sim`）及真机端到端评测底座 **`mindie-bench`**，随附 **7 大昇腾公共领域知识库（共 `450` 个 `L1–L4` 分级知识单元）**，并在 **`codex + gpt-6.1-sol (xhigh)`** 与 **`dsh + deepseek-flash (max)`** 双主力模型、**18 个真实昇腾工程任务（109 场端到端 Trial，含 `Ascend950DT` 实机 NPU）** 以及 **macOS / 4090 WSL2 / Windows 11 PowerShell 三平台（`15,595+ passed, 0 failed`）** 上完成了系统性价值量化验证。

### 1.1 原生宿主适配层（4 个 Harness 插件：`cc` / `codex` / `kimi` / `dsh`）

1. **“去 Skill 化”与单一入口（`/mindie-agent` + `rsi-explore`）**：
   - **彻底剥离工具与知识**：传统多 Skill 架构会将数百个 Skill 的 `name` 与 `description` 强行注入宿主上下文，不仅挤占宝贵的注意力窗口，更频繁引发自然语言路由误命中与脚本重复维护。MindIE Agent 将传统 Skill 拆解为正交的两大支柱——**按单一职责收敛的标准 MCP 工具集**与**按需检索的 `L1–L4` 分级知识库**；
   - **无感工具常驻 + 单一知识入口**：远端执行底座 `remote-dev` 作为原生对等工具常驻就绪；领域知识与调优工作流仅保留唯一入口 `/mindie-agent`（OpenAI Codex CLI 为 `$mindie-agent`），并在需要突破历史先验的深度算子/图融合探索中提供 `rsi-explore` 切换入口。
2. **四阶段任务生命周期与统一授权开关（`mindie-consent.json`）**：
   - **阶段一（`SessionStart` 非阻塞就绪与空闲原子切换）**：会话启动时以毫秒级延迟完成本地 MCP 服务拉起；已就绪的 MCP 服务不再阻塞等待可选的知识库增量同步锁；若后台更新器已构建好新版本环境，则在空闲窗口内以 `< 500ms` 排他锁完成原子指针切换；
   - **阶段二（任务执行期渐进式检索与远端 NPU 执行）**：Agent 先调用 `knowledge_query` 获取轻量级候选卡片摘要与 `applicability` 适用前提，再按需调用 `knowledge_explain` 分段读取正文，并通过 `remote-dev` 及专业分析组件在远端昇腾容器内闭环执行；
   - **阶段三（`Stop` 异步采集、双层脱敏与 `C6` 经验蒸馏）**：会话自然结束时，后台异步提取公开对话轨迹（严格隔离未公开的跨目录 Fork 会话），在本地依次执行**确定性正则 + `Gitleaks` 双层隐私脱敏**（彻底剥离内网 IP、SSH 凭据、API Key 与宿主机私有路径），再经由 `C6` 蒸馏器提炼为结构化 `L1–L4` 知识单元并过滤未验证假设；
   - **阶段四（统一 Opt-in 贡献与故障上报开关）**：自 `0.0.2` 起，社区知识共享（自动 Fork 发起公开 PR）与工具内部故障上报（自动提交脱敏 GitHub Issue）合并为安装配置中的单一开关 `mindie-consent.json`（默认关闭）。用户撤回授权后立即中断知识外发与故障上报两条链路并清理待发队列；当网络或 GitHub 认证瞬时不可用时保留本地队列延后重试，绝不因瞬时错误丢弃回执。
3. **三端九环境跨平台进程树与环境隔离**：
   - **macOS (`launchd`)**：通过独立应用数据目录与 `launchd` 守护任务管理后台更新、知识增量同步与异步摘要 worker；
   - **Linux / Windows WSL2 (`systemd >= 254`)**：基于用户级 `systemd` 控制组（cgroup）实现子进程树精确回收、SIGTERM 终态回执记账与陈旧搁浅回执自动退役（`knowledge v0.11.3+`）；在缺少系统级 `python3-venv` 的精简镜像中自动由 `uv venv` 兜底；
   - **原生 Windows 11 PowerShell**：通过 Windows `Job Object`（`KILL_ON_JOB_CLOSE`）确保中断或超时时完整回收子进程树；采用短路径虚拟环境目录布局规避 Windows `MAX_PATH` 限制；修复 `Task Scheduler` 计划任务命令截断与 Session-0 精简 `PATH` 下的 `git` 确定性解析；将 DSH 摘要 worker 部署至持久化应用数据目录，彻底消除宿主机全局 Python 环境污染与孤儿进程残留。

   | 公共知识库仓库 | 覆盖领域与核心内容 | 分级单元数 | `L1–L4` 层级职能定义 |

2. **两阶段渐进式披露与 `< 8,000` Tokens 预算门控（彻底解决 `0.0.2` 长上下文检索拖慢问题）**：
   - 在 `0.0.2` 评测中，我们如实披露了“一次性读取长篇知识正文会增加额外交互轮次与 Token 开销，导致单任务耗时比回落至 `0.595x–0.975x`”的问题；
   - `knowledge v0.13.0` 通过**两阶段渐进式披露（Progressive Disclosure）**彻底攻克该瓶颈：第一阶段 `knowledge_query` 仅返回高信噪比候选索引、层级标签与 `applicability` 适用前提（单条摘要 `< 1.2 KB`），由 Agent 自行判断命中的卡片是否契合当前芯片架构与报错上下文；第二阶段 `knowledge_explain` 仅对选中的目标单元按需分段加载正文；
   - 在 P0–P4 渐进式披露基准套件（21 项子测试）中，`technical-tokenization` 检索精度达 **`1.0`**，`graded-feed-lifecycle` 耗时仅 **`~13.8 ms`**，**单次任务知识读取开销严格受控在 `4,814–5,599` tokens（远低于 `8,000` tokens 预算上限）**，并在跨任务复用（`k=8`）下实现 **`+77,280 ~ +89,120` tokens** 的净工程收益。
3. **`G3` 经验自进化飞轮（`seed -> Stop 采集 -> C6 蒸馏 -> eval`）**：
   - 当开发者或 Agent 首次攻克一个公共知识库尚未覆盖的新型故障（`seed` 任务）后，`Stop` Hook 自动采集公开对话轨迹、完成双层脱敏，并调用 `C6` 蒸馏流水线生成包含明确触发判据与修复步骤的 `L1–L3` 知识单元（同时剔除过程中失败的未验证猜测）发布入库；
   - 当后续同族新任务（`eval` 任务，例如换了模型头维度配置且底层 C++ 源码已被剥离为黑盒 `.so` 的线上故障）到来时，Agent 仅需 `1` 次 `knowledge_query` + `1` 次 `knowledge_explain` 即可直接复用前序沉淀的契约，实现从“反复盲猜失败（`0%`）”到“一次精准解出（`100%`）”的质变。
4. **`G4` 开放式探索与去先验锚定（`mode="reuse" -> mode="explore"`）**：
   - 针对常规 `L3` 历史经验无法收敛的多因子算子融合与模型图优化任务，`knowledge v0.13.0` 引入了源自 RSI（递归自我改进）理念的 **`mode="explore"` 独立探索模式**与原生子上下文事实包组装接口（`assemble_subcontext_fact_pack`）；
   - 当 Agent 判定常规检索（`mode="reuse"`）无法突破瓶颈时，切换至 `mode="explore"`：检索引擎自动**物理屏蔽既有 `L3/L4` 具体历史实现方案以消除先验锚定**，仅挂载 `L1` 硬件刚性边界（如 `192 KiB` UB 容量上限）、`L2` 实测瓶颈判据、已证实无效的避坑清单（`conditional_avoid`）以及 `L4` 正交变异因子图谱（`factor_graph`）与留一法消融计划（`leave_one_out_plan`），指导 Agent 在隔离环境中完成多因子正交实现并生成 `experiment-ledger.jsonl` 留一法消融台账。

### 1.3 七大共享运行时、可观测与性能建模组件（7 Shared Runtime & Modeling Components）

1. **`remote-dev`（`v0.9.5 -> v0.10.4`，远端昇腾容器对等执行底座）**：
   - **1:1 本地同构对等工具集**：提供与宿主原生本地工具入参、返回格式完全一致的 `remote_` 前缀工具集（远端文件读写、结构化补丁解析与应用、Git、代码搜索及持久后台长作业流式管理），搭载 SSH ControlMaster 连接复用，彻底免除 Agent 每一轮手写复杂 SSH 转义命令的 Token 损耗；
   - **独立超时预算与诚实外部副作用记账**：将持久后台作业控制、RPC 握手与多阶段 SSH 隧道诊断纳入各自独立的超时预算；严格区分 `completed`、`failed` 与 `unknown`（外部写入状态未知），绝不将远端命令执行失败伪装为 `exit 0`，也绝不因本地回执记账超时覆盖已成功的远端业务输出。
2. **`coordinator`（`v0.5.3 -> v0.6.2`，多 Agent 资源租约与集群拓扑管家）**：
   - **SQLite WAL 选卡与端口租约队列仲裁**：彻底解决多 Subagent 并发跑任务时因“先检查空闲再绑定”竞态导致的抢卡与端口冲突。在 3 轮双 Agent 并发抢占压测中，接入 `coordinator` 后**有效监听数从 `3` 翻倍至 `6`（每轮 `1 -> 2`），端口冲突从 `3` 降为 `0`，重复选卡从 `3` 降为 `0`**，前序任务释放后等待方平均仅需 **`2.1 ms`** 即完成租约接管；
   - **昇腾 A2 / A3 双 Die / A5 全代际拓扑预检与编译缓存复用**：支持昇腾 A2（910B）、A3（910C 一卡双 Die `Phy-ID` 兄弟绑定与 PD 分离整卡隔离）及 A5（`Ascend950DT`）`npu-smi` 拓扑探测、多机 `distinct_hosts` 放置仲裁、HCCL/RoCE 联通性预检，以及新分配机器自动免密配置与跨机算子编译产物缓存复用（避免仅修改 Python 代码时重复触发长达数十分钟的 AscendC 算子重编）。
3. **`npu-top`（`v0.1.9 -> v0.2.1`，昇腾物理拓扑、容器归属与健康度实时观测）**：

### 5.2 `0.1.0` 里程碑 + `0.1.x`（`channels/0.1.json`）轻量级单组件热修机制

从 `0.1.0` 起，MindIE Agent 采用 **`0.Y.0` 特性里程碑 + `0.Y.Z` 通道清单热修（[`channels/0.1.json`](../../channels/0.1.json)，`schema: "mindie-release-channel/1"`）** 的解耦演进机制：
- **消除四插件连坐重发**：当单个底层组件（如 `remote-dev`、`diagnostics` 或 `knowledge`）发布 `0.1.1` / `0.1.2` 缺陷修复时，只需更新 `channels/0.1.json` 中对应组件的 `version`、`tag` 与 `commit` SHA，客户端即可在后台基于 `uv` 缓存执行单包增量替换，并在服务空闲窗口内以 **`< 500ms`** 完成原子指针切换，**无需重新打包并连坐重发 4 个宿主插件 Release**；
- **三层极速触达**：支持 **(1) 故障触发即时自愈检查**（`hotfix_trigger_on_error: true`，遭遇非预期异常时立即旁路 24 小时冷却检查热修补丁）、**(2) 1 小时轻量级 HTTP `ETag` 轮询**（`etag_poll_interval_sec: 3600`，未变更时 `304 Not Modified` 零解析开销）以及 **(3) 7 大昇腾知识库 `feed_sync` 零代码热加载**。
