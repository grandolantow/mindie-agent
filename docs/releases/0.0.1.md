# MindIE Agent `0.0.1` 版本发布记录

[English](0.0.1.en.md) · [返回文档中心](../README.md)

`0.0.1` 是 MindIE Agent 的首个正式内测发行版（Git Tag 为 `v0.0.1`，在 GitHub Releases 上均为 `draft=false`、`prerelease=false` 的正式 Release）。本文汇总本次发布的配套组件映射、支持的宿主与操作系统矩阵、已验证的核心能力以及已知宿主限制。

| 环境组合 | 支持的宿主 CLI 版本 | 环境要求与验证范围 |

## 3. 已验证的核心能力

1. **原生安装与 24 小时后台无感更新**：
   - 首次安装固定不可变 `v0.0.1` 标签；距上次成功检查超过 24 小时后，日常使用异步匹配当前宿主的最高兼容正式版，在锁外构建环境并趁空闲时原子切换，全程保留既有用户授权。
2. **远端昇腾 NPU 执行与本地经验闭环**：
   - 六个环境均通过 `remote-dev` 完成了真实的远端昇腾服务器命令执行、文件读取与状态检查，并自动完成公开对话提取、Gitleaks + 隐私规则脱敏、小模型导航索引生成及本地 ReMe 检索验证。
3. **社区知识贡献、Bot 审核与增量同步**：
   - 验证了任务知识包自动发起公开 PR、Grok Bot 安全合规审核并合入 [`knowledge-vllm-ascend`](https://github.com/mindie-agent/knowledge-vllm-ascend)、新客户端增量同步（661 个任务包）以及 `helpful` 反馈闭环。
4. **有界本地诊断与可选故障上报**：
   - 验证了本地结构化诊断日志轮转、跨任务故障指纹去重以及独立授权下的 GitHub Issue 自动故障上报。
5. **DeepSeek Harness 原生接入（补录验收）**：
   - 在 macOS 27.0.1 arm64、4090 WSL (Ubuntu 24.04) 与 Lenovo 原生 Windows + DSH `0.2.0-rc.2` 上验证了 Host 行组合（不覆盖任何内置行/预设）、原生 `/mindie-agent` 入口（`init`/`status`/`choose`/`deactivate`）、DSH v4 Stop 公开对话采集+脱敏、DSH 模型摘要索引、自动 fork 贡献（PR #51）、`knowledge_query` / `knowledge_explain` / `knowledge_feedback` / `knowledge_sync`、诊断上报控制、静默自动更新（稳定 launcher + 不可变 generation + 原子指针热切换），以及官方 `remote-dev` MCP 工具接入与可见失败路径。

## 4. `0.0.1` 已知限制说明

- **OpenAI Codex CLI 子代理（Subagent）取消信号缺口**：
  - 在 OpenAI Codex CLI 中，当主会话被中断或显式中断子代理（`spawn_agent`）时，Codex 上游目前仅中断主线程等待句柄，尚未向子代理正在执行的 MCP 工具调用传递取消信号，可能导致子代理拉起的本地辅助进程或单次远端命令继续运行直至自然结束（主线程直接调用的工具取消以及 Claude Code 取消均已正常工作）。
  - MindIE Agent 如实记录该上游限制，不在插件内引入高侵入性的私有杀进程守护或武断超时；通过 `remote-dev` 启动的远端持久后台作业始终可通过 `job_cancel` 显式停止。我们已在 [openai/codex#26956](https://github.com/openai/codex/issues/26956#issuecomment-6205886409) 附上最小复现与修复分析，待上游正式发布修复后更新支持区间。
- **评测与宿主范围边界**：
  - 端到端业务提效基准评测（Benchmark）作为独立事项推进，`0.0.1` 不预先宣称量化提效比例。
- **DSH `0.0.1` 已知限制**：
  - 自动更新在 DSH Host 运行期间按启动/定时间隔检查并热切换子插件，不额外注册停止状态下的 OS 定时任务；Generation 热切换更新 launcher/host 工具，不重新生成初始 bundle 补丁或 Skills；详细平台级说明见 [`mindie-agent-dsh/docs/verification.md`](https://github.com/mindie-agent/mindie-agent-dsh/blob/main/docs/verification.md)。
