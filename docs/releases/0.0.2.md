# MindIE Agent `0.0.2` 版本发布说明

[English](https://github.com/mindie-agent/mindie-agent/blob/v0.0.2/docs/releases/0.0.2.en.md) · [文档中心](https://github.com/mindie-agent/mindie-agent/blob/v0.0.2/docs/README.md)

本文记录 MindIE Agent `0.0.2` 的功能更新、配套组件清单、核心组件实测结果与使用注意事项。

在 `0.0.2` 中，主产品与 OpenAI Codex CLI、Claude Code、Kimi Code、DeepSeek Harness（DSH）四个宿主插件统一对齐为 `0.0.2` 版本；底层共享运行时组件与评测工具 `mindie-bench`（`0.3.0`）保持各自独立的版本号。本次发布重点完成了统一贡献与故障上报开关、跨组件边界收敛、固定依赖安装闭环，并交付了核心组件的真实任务实测报告。

---

## 一、核心更新

- **统一贡献与故障上报开关**：社区知识共享与工具故障自动上报合并为同一个贡献开关（以安装配置中的 `mindie-consent.json` 为准，默认关闭）。显式开启后自动准备知识贡献配置并启动系统后台上报服务；关闭后立即停止知识外发与故障上报两条链路，本地诊断日志与远端开发工具不受影响。当网络或 GitHub 认证暂时不可用时保留待发队列并延后重试，不会因瞬时查询失败丢弃故障记录。
- **远端开发与多 Agent 资源协调**：
  - `remote-dev` 将持久后台作业控制、RPC 握手与多阶段 SSH 诊断纳入独立超时预算；远端命令执行成功时完整保留业务输出，并明确区分执行失败与外部写入状态未知（`unknown`）。
  - `coordinator` 支持多 Agent 并发场景下的 NPU 选卡与端口租约仲裁，并在提交任务时实时解析当前 Git 源码版本，避免沿用旧缓存。
- **宿主客户端体验与跨平台稳定性**：
  - **Claude Code**：优化首次冷启动状态初始化，已就绪的 MCP 服务不再阻塞等待可选知识库同步锁；
  - **OpenAI Codex CLI**：缩短 Windows 默认用户目录布局下的虚拟环境目录标识，解决依赖路径超出传统 Windows 路径长度限制的问题；
  - **Kimi Code CLI**：支持正式 Release 版本兼容性筛选与原子升级切换（Windows 原生环境要求 Python 3.12 及以上，优先选择 3.13）；
  - **DeepSeek Harness (DSH)**：将摘要 worker 部署至持久化应用数据目录，移除安装临时目录后仍可正常运行，并在安装超时时完整回收子进程树；
  - **共享运行时收敛**：移除各插件内重复维护的诊断 fallback 与授权 bootstrap 副本，统一直接调用锁定的共享运行时组件。

## 三、实测收益与 `0.0.3` 优化计划

完整实验配置与逐轮数据见 [`0.0.2` 评测报告（`value-results.md`）](https://github.com/mindie-agent/mindie-agent/blob/v0.0.2/docs/releases/0.0.2/value-results.md)。

### 1. `remote-dev` 与 `coordinator` 的实测收益

- **`remote-dev`（`v0.10.1`，远端昇腾容器开发与执行底座）**：
  - 在 `vLLM-Ascend` 复杂量化修复任务（`quarot`，3 轮重复）对照中，接入 `remote-dev` 后 **`3/3` 全部解出，且端到端交付提速 `1.025x`（累计交付耗时从 `564.39s` 降至 `550.89s`）**；
  - 在跨机双卡排障任务（`dp2`）中，解出率与耗时（`0.963x`）与本地直连基线保持一致，同时将跨机 SSH、容器内文件读写、代码补丁应用与持久后台作业统一收敛为结构化工具调用。
- **`coordinator`（`v0.5.3`，多 Agent 并发租约与端口/选卡仲裁）**：
  - 在 3 轮双 Agent 并发抢占实测中，无协调基线（“先检查空闲再绑定”）因并发竞争仅成功建立监听 `3` 个，并出现 `3` 次端口冲突与 `3` 次重复选卡；
  - 接入 `coordinator` 租约队列后，**成功建立监听数从 `3` 提升至 `6`（`3 → 6`），端口冲突降为 `0`（`3 → 0`），重复选卡降为 `0`（`3 → 0`）**，前序任务释放后等待任务约 **`2ms`** 即可完成接管。

### 2. `npu-top` 与 `diagnostics` 组件实测

- **`npu-top`（`v0.1.9`）**：支持昇腾 A2（910B 单 Die）与 A3（910C 双 Die `Phy-ID`）节点在空闲或忙碌状态下的实时硬件探测；在 3 轮硬件快照与实机容器探测中，24 张物理卡识别、`16/16` 个进程归属映射与 `3/3` 实机容器归属校验全部通过。
- **`diagnostics`（`v0.4.3`）**：支持跨平台后台服务（macOS `launchd` / Windows `Task Scheduler`）的故障自动去重与白名单隐私脱敏（仅上报组件版本、Commit SHA 与白名单执行元数据，绝不包含对话、命令参数或本机路径）；在 3 轮上报测试中，9 次受控故障自动去重收敛为 3 条报告，关键字段保留、隐私脱敏与撤回授权后立即停发均为 `3/3` 通过。

### 3. 知识系统（`knowledge` + Skills）表现与 `0.0.3` 优化计划

- **解题完成率与跨任务经验复用**：
  - 启用 `knowledge` 检索与随包 Skills 后，`dp2`（Codex）与 `dsh` 任务的完成数均从 `2/3` 提升至 **`3/3`**；
  - 在跨任务经验复用实验（先完成 1 个前置任务沉淀经验，再执行 2 个不同后续任务，共 3 轮）中，6 个后续任务有 **`5/6`** 次直接检索命中并读取了前置任务沉淀的经验，后续任务结题速度比达 **`1.011x`**（`6/6` 配对全部解出）。
- **预计 `0.0.3` 优化方向**：
  - 当前版本在检索与阅读长上下文时增加了额外的交互轮次与 Token 开销，导致单次任务整体耗时相比不启用检索的基线仍有一定拖慢（耗时比 `0.595x–0.975x`）。
  - **预计在 `0.0.3` 版本重点优化 `knowledge` 的检索触发门控与上下文精简**，在保持解题率提升与跨任务经验复用能力的同时降低单任务与全流程耗时。

## 四、DSH `0.0.2` 同版本刷新说明

按产品版本对齐安排，`mindie-agent-dsh` 本次保持 `0.0.2` 版本号，对早先发布的旧版 `0.0.2`（源码 `828c375d1f546ed653250526465b8075c1691390`）进行同版本更新，最新配套源码见本文上方组件表。

- **升级提示**：由于旧版更新器仅自动拉取高于当前已安装版本号的 Release，**此前已安装过旧版 DSH `0.0.2`（`828c375...`）的环境不会自动更新**。
- **操作方式**：请参照 [`same-version-refresh.md`](https://github.com/mindie-agent/mindie-agent-dsh/blob/main/docs/same-version-refresh.md) 按精确源码 SHA 显式刷新一次共享运行环境（`setup.py`）与 DSH 插件包，并**重启整个 DSH 进程**。刷新过程完整保留已有的用户授权与本地知识数据；后续更高版本将恢复常规自动更新。

---

## 五、使用注意事项

- **升级后的贡献开关默认保持关闭**：旧版本中处于 `disabled`、`later`、`read-only` 状态，或仅开启过早期知识贡献（`contribute`）但未确认统一贡献开关的配置，升级到 `0.0.2` 后**不会**自动开启故障上报，需由用户显式开启一次统一贡献开关。
- **Windows 运行权限一致性**：在 Windows 环境下，请保持宿主 CLI 与后台计划任务在同一普通桌面用户权限下运行；若以管理员提升权限运行宿主 CLI，其创建的私有状态目录可能无法被普通权限计划任务读取。若企业终端启用了拦截 `pythonw.exe` 的强制应用控制策略，后台自动采集与上报将无法启动，但不影响前台 MCP 工具正常使用。
