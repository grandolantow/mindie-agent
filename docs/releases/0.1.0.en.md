# MindIE Agent `0.1.0` Official Release Notes (First Official Milestone Release)

[中文](0.1.0.md) · [Documentation Center](../README.en.md) · [Release Compatibility & Silent Update](../release-compatibility-and-update.en.md)

**`v0.1.0` is the First Official Milestone Release of MindIE Agent.**

This release consolidates the entire architectural evolution from our internal preview releases ([`0.0.1`](0.0.1.en.md) $\to$ [`0.0.2`](0.0.2.en.md) $\to$ [`0.0.3`](0.0.3.en.md)) into a production-ready Ascend NPU AI Infra harness and runtime ecosystem: native integration across **4 coding agent hosts** (`Claude Code`, `OpenAI Codex CLI`, `Kimi Code CLI`, `DeepSeek Harness`), **7 shared runtime, observability, and performance modeling components** (`remote-dev`, `knowledge`, `diagnostics`, `coordinator`, `npu-top`, `profiler`, `sim`) plus the end-to-end benchmark runner **`mindie-bench`**, **7 public Ascend domain knowledge corpora (`450` `L1–L4` graded knowledge units)**, and systematic real-task benchmark validation across **`codex + gpt-6.1-sol (xhigh)`** and **`dsh + deepseek-flash (max)`** (**18 real engineering tasks, 109 end-to-end trials including live `Ascend950DT` NPUs**) as well as **macOS / 4090 WSL2 / Windows 11 PowerShell (`15,595+ passed, 0 failed`)**.

### 1.1 Native Host Adaptation Layer (4 Harness Plugins: `cc` / `codex` / `kimi` / `dsh`)

1. **"De-Skilling" & Single Entry Point (`/mindie-agent` + `rsi-explore`)**:
   - **Orthogonal Separation of Tools and Knowledge**: Traditional multi-Skill architectures force hundreds of Skill `name` and `description` entries into the Harness context window, polluting attention, causing natural-language routing false positives, and duplicating helper scripts. MindIE Agent decomposes Skills into two orthogonal pillars: **Single-Responsibility MCP Tools** and **On-Demand `L1–L4` Graded Knowledge**;
   - **Always-On Peer Tools + Single Knowledge Entry**: `remote-dev` stays registered as an always-on native peer toolset, while domain knowledge and workflows are invoked on demand through a single `/mindie-agent` entry point (`$mindie-agent` in OpenAI Codex CLI), complemented by `rsi-explore` for open-ended operator/graph exploration.
2. **Four-Stage Task Lifecycle & Unified Opt-In Consent (`mindie-consent.json`)**:
   - **Stage 1 (`SessionStart` Non-Blocking Readiness & Atomic Cutover)**: Starts local MCP servers within milliseconds without blocking on optional knowledge feed sync locks; if a staged update is ready, performs an atomic pointer switch in `< 500ms` during an idle window;
   - **Stage 2 (Task Execution: Two-Stage Progressive Retrieval & Remote NPU Execution)**: The Agent queries compact candidate cards via `knowledge_query`, selectively reads relevant sections via `knowledge_explain`, and executes changes on remote Ascend containers via `remote-dev` and specialized components;
   - **Stage 3 (`Stop` Async Capture, Dual-Layer Redaction & `C6` Distillation)**: At session end, extracts public transcripts asynchronously (strictly isolating private cross-directory forked sessions), runs **deterministic regex + `Gitleaks` dual-layer privacy scrubbing** locally (stripping internal IPs, SSH credentials, API keys, and local paths), and distills verified findings into structured `L1–L4` units via the `C6` pipeline while filtering out unverified hypotheses;
   - **Stage 4 (Unified Opt-In Contribution & Fault Reporting Switch)**: Controlled by a single `mindie-consent.json` switch (OFF by default). Revoking consent immediately halts both knowledge PR submission and fault Issue reporting and clears pending queues; transient network/GitHub auth failures preserve queued items for retry without silent drops.
3. **Three-OS Nine-Environment Process-Tree & Environment Isolation**:
   - **macOS (`launchd`)**: Isolated application data directories and `launchd` agents for background updates, feed sync, and summary workers;
   - **Linux / Windows WSL2 (`systemd >= 254`)**: User-level `systemd` cgroup process-tree cleanup, SIGTERM terminal receipt accounting, stranded receipt retirement (`knowledge v0.11.3+`), and automatic `uv venv` fallback on minimal Ubuntu images;
   - **Native Windows 11 PowerShell**: Windows `Job Object` (`KILL_ON_JOB_CLOSE`) process-tree termination on interrupt/timeout, short-path virtualenv layout to avoid `MAX_PATH` limits, deterministic `git` resolution under Session-0 `Task Scheduler` environments, and persistent app-data deployment for the DSH summary worker.

2. **Two-Stage Progressive Disclosure & `< 8,000` Token Budget Gate (Solving the `0.0.2` Context Overhead)**:
   - In `0.0.2`, loading full knowledge documents upfront added extra turns and token overhead (`0.595x–0.975x` single-task speed ratio);
   - `knowledge v0.13.0` introduces **two-stage progressive disclosure**: `knowledge_query` returns only compact candidate summaries and `applicability` preconditions (`< 1.2 KB` per card), and `knowledge_explain` loads full sections on demand;
   - Across the 21-test P0–P4 suite, `technical-tokenization` precision reached **`1.0`**, `graded-feed-lifecycle` completed in **`~13.8 ms`**, **per-task knowledge read overhead stayed strictly within `4,814–5,599` tokens (well below the `8,000`-token ceiling)**, and cross-task reuse (`k=8`) delivered **`+77,280 to +89,120` tokens** in net savings.
3. **`G3` Self-Evolving Experience Flywheel (`seed -> Stop capture -> C6 distillation -> eval`)**:
   - After solving a novel bug (`seed` task), the `Stop` hook sanitizes the public transcript and runs `C6` distillation to publish a verified `L1–L3` knowledge unit (filtering out failed guesses), enabling unseen downstream sibling tasks (`eval`, including black-box `.so` tasks with C++ sources stripped) to pass on the first attempt.
4. **`G4` Open-Ended Exploration & De-Anchoring (`mode="reuse" -> mode="explore"`)**:
   - When standard `L3` workflows stall on complex operator/graph fusion tasks, switching to `mode="explore"` **physically strips away existing `L3/L4` concrete recipes to prevent prior anchoring**, retaining only `L1–L3` physical constraints, `conditional_avoid` dead-end guards, and `L4` composable `factor_graph` mutators with a `leave_one_out_plan` verified via `experiment-ledger.jsonl`.

### 1.3 Seven Shared Runtime, Observability & Performance Modeling Components

1. **`remote-dev` (`v0.9.5 -> v0.10.4`, Remote Ascend Container Execution Foundation)**:
   - **1:1 Local-Isomorphic `remote_` Toolset**: Mirrors native host file, patch, Git, search, and streaming background job tools over multiplexed SSH ControlMaster connections, eliminating repetitive SSH quoting and wheel-reinvention;
   - **Independent Timeout Budgets & Honest Side-Effect States**: Separates RPC handshake, background job control, and multi-stage SSH diagnostics into independent timeout budgets, and strictly distinguishes `completed`, `failed`, and `unknown` external writes without masking errors or overwriting succeeded remote outputs.
2. **`coordinator` (`v0.5.3 -> v0.6.2`, Multi-Agent NPU Lease & Cluster Topology Manager)**:
   - **SQLite WAL Device & Port Lease Queue**: Eliminates check-then-bind race conditions when multiple Subagents run concurrently. Across 3-round dual-Agent contention benchmarks, **active listeners doubled from `3` to `6` (`1 -> 2` per round), port bind conflicts dropped from `3` to `0`, duplicate card selections dropped from `3` to `0`**, and lease handoff completed in **`~2.1 ms`**;
   - **Ascend A2 / A3 Dual-Die / A5 Topology Pre-Checks & Build Cache Reuse**: Supports A2 (910B), A3 (910C dual-Die sibling `Phy-ID` binding and PD-disaggregated whole-card isolation), and A5 (`Ascend950DT`) topology discovery, multi-host `distinct_hosts` placement, HCCL/RoCE pre-checks, automated SSH key setup, and cross-machine AscendC build cache reuse.
3. **`npu-top` (`v0.1.9 -> v0.2.1`, Real-Time Ascend Physical Topology, Container Ownership & Telemetry)**:
   - **A3 Dual-Die `Phy-ID 0..15` Mapping & `/proc` Container Attribution**: Maps card-local `Chip ID (0, 1)` to global physical `Phy-ID (0..15)` with card-level HBM aggregation and Linux `/proc` Docker container ownership resolution (**`24/24` physical devices, `16/16` process mappings, and `3/3` live container attributions verified**);
   - **DCMI Throttling Decoder & 90-Day Utilization Heatmaps**: Decodes DCMI thermal (`bit 2`) and power (`bit 3`) throttling bitmasks and aggregates fractional time-window utilization.
4. **`profiler` (`v0.5.0`, Millisecond In-Place Read-Only `msprof` Attribution & P0–P4 Memory Breakdown)**:
   - **Zero-Mutation In-Place SQLite Analysis**: Provides `inventory`, `analyze`, `correlate`, `compare`, and `sql` primitives over raw `msprof` SQLite databases (`db_mutation = False`), completing aligned step analysis in **`~8.6 ms`**, cross-rank comparison in **`~0.17 ms`**, and memory attribution in **`~0.13 ms`**;
   - **100% Slow-Link vs. Slow-Rank Separation & 99% Peak HBM Attribution**: Computes multi-stream interval unions (`busy_union_ms`) and exposed communication (`exposed_comm_ms`) to **100% separate slow links (`Comm`) from slow ranks (`Attention`)**, and attributes **`9.9 GB` (`99%`)** of a `10.0 GB` peak HBM footprint into known P0–P4 non-additive buckets with only **`50 MB` (`0.5% < 10%` gate)** unattributed residual.
5. **`sim` (`v0.7.0`, Ascend A2/A3/A5 Four-Layer Roofline & Operator Pipeline Simulator)**:
   - **Four-Layer Full-Stack Modeling**: Covers Layer 1 Hardware Roofline ($T_{\text{HW}}$) and HAP scoring, Layer 2 Cube/Vector/MTE finite pipeline scheduling (`gemm_finite_pipeline`, `vector_instruction`, loop `minimum_tile_ii_ns`), Layer 3 Subgraph `UB` capacity screening, and Layer 4 multi-node collective communication (A3 3-tier `intra_package` / `intra_node` / `inter_node`) and network parallelism;
   - **`-4.14%` Calibrated A3 Network Prediction & 100% UB Overflow Rejection**: Predicts Ascend A3 Qwen2.5-7B-Instruct `c=1` TPOT at **`15.06 ms`** vs. **`15.71 ms`** measured on live A3 hardware (**`-4.14%` error**, well within the `±15%` gate), identifies **`2.0 MiB` removable GM traffic** and **`5.0 μs` critical-path savings**, and **100% rejects UB-overflowing fusion candidates** (`subgraph_overflow_rejected = True`).
6. **`diagnostics` (`v0.4.1 -> v0.5.1`, Deterministic CANN/`plog` Root-Cause Triage & Privacy-Safe Fault Reporting)**:
   - **Deterministic Multi-Rank Cascade Triage (`analyze_fault_log`)**: Automatically separates originating root-cause ranks (e.g., `Rank 3` `EZ9999` `aicore_memory_or_tiling` or `Rank 0` `E89999` `device_oom_or_driver`) from downstream ranks logging cascading `HCCL_E_WAIT_TIMEOUT` (`EI9999` / `EI0006`);
   - **Mandatory Dual-Layer Redaction, Deduplication & `uncertain` Outbox Guard**: Enforces regex + `Gitleaks` redaction before triage/reporting (`fault_log_redacted = True`), deduplicates repeated faults (`3 -> 1`), and preserves `uncertain` state on external POST timeouts to prevent duplicate Issue creation (`blind_retry_prevented = True`).
7. **`mindie-bench` (`v0.3.0 -> v0.4.1`, Four-Harness `G0–G4` End-to-End Evaluation Runner)**:
   - Supports `G0–G4` ablation matrices across `codex`, `claude-code`, `kimi`, and `dsh`, task soundness gates (`before_reward=0.0 -> after_reward=1.0`), L3 live Ascend NPU slot isolation, and component attribution audits.

### 3.1 Host Prompt Construction Contract (`build_agent_prompt`)

In [`mindie-bench`](https://github.com/mindie-agent/mindie-bench), each trial sends **a single initial prompt** with zero human intervention (`human_interventions = 0`):

```text
Prompt = knowledge_prompt(group, harness) + task_instruction_md + workspace_scope_suffix
```

- **`knowledge_prompt(group, harness)` (the only prefix difference across ablation groups)**:
  - **`G0` (Bare Host) & `G1` (`remote-dev` only)**: `""` (empty string; no mention of MindIE knowledge or Skills);

    - OpenAI Codex CLI: `$mindie-agent\n\n`
    - Claude Code / Kimi Code / DeepSeek Harness (DSH): `/mindie-agent\n\n`
- **`workspace_scope_suffix` (identical across all groups within the same tier)**:
  - **L2 Local Snapshot**:
    ```text
    The workspace is a plain source snapshot without Git history. Apply the repair here and use the public reproducer or relevant available tests for validation. Git history, stash and checkout are unavailable. Choose validation proportional to the change and observed failures; report any unavailable dependencies in your final answer.
    ```
  - **L3 Remote Live Ascend NPU**:
    ```text
    Work on the isolated SSH endpoint bench-slot. Remote workspace: <remote.path>. Assigned NPU devices: <devices>. The local directory is an empty client scratchpad; the source snapshot lives in the remote workspace on bench-slot without Git history. Apply the repair in the remote workspace that the NPU verifier will inspect. Choose validation proportional to the change and observed failures.
    ```

### 5.2 `0.1.0` Milestone + `0.1.x` (`channels/0.1.json`) Lightweight Single-Component Hotfixes

Starting with `0.1.0`, MindIE Agent adopts a **`0.Y.0` Feature Milestone + `0.Y.Z` Release Channel Manifest ([`channels/0.1.json`](../../channels/0.1.json), `schema: "mindie-release-channel/1"`)** model:
- **No Coupled 4-Plugin Republishing**: When a single shared component (e.g., `remote-dev`, `diagnostics`, or `knowledge`) ships a `0.1.1` / `0.1.2` patch, updating its `version`, `tag`, and `commit` SHA in `channels/0.1.json` rolls out an incremental `uv` single-package update in the background and switches atomically in **`< 500ms`** during an idle window—**without republishing all four Harness plugins**;
- **Three-Tier Rapid Rollout**: Combines **(1) Fault-triggered immediate self-healing** (`hotfix_trigger_on_error: true`, bypassing the 24h cooldown on unexpected tool failures), **(2) 1-hour lightweight HTTP `ETag` polling** (`etag_poll_interval_sec: 3600` with `304 Not Modified` fast path), and **(3) Zero-code `feed_sync` hot-reloading** across all 7 public Ascend corpora.
