# MindIE Agent `0.1.0` Release Notes (Milestone & `0.1` Release Channel)

[中文](0.1.0.md) · [Documentation Center](../README.en.md) · [Release Compatibility & Silent Update](../release-compatibility-and-update.en.md)

This document records the core architectural updates in the MindIE Agent `0.1.0` milestone release, the [`channels/0.1.json`](../../channels/0.1.json) Release Channel Manifest mechanism, the exact 12-repository source manifest, and the specification for `0.1.x` (`0.1.1`, `0.1.2`, ...) single-component hotfixes and three-tier rapid rollout.

Starting with `0.1.0`, MindIE Agent adopts a two-tier **`0.Y.0` Feature Milestone + `0.Y.Z` Release Channel Manifest** SemVer model:
- **`0.Y.0` (`0.1.0` → `0.2.0`)**: Represents major feature milestones with full release notes (`docs/releases/0.1.0.md` / `docs/releases/0.1.0.en.md`) and 12-repository benchmark verification;
- **`0.Y.Z` (`0.1.1`, `0.1.2`, ...)**: Represents rapid bugfix and single-component updates driven by [`channels/0.1.json`](../../channels/0.1.json) (`schema: "mindie-release-channel/1"`). When a single shared component (such as `remote-dev`, `diagnostics`, or `knowledge`) ships a bugfix, updating its version, tag, and commit SHA in `channels/0.1.json` rolls out an incremental single-package `uv` replacement (`< 500ms` under atomic idle switch) **without requiring all four Harness plugins (`mindie-agent-codex`, `mindie-agent-cc`, `mindie-agent-kimi`, `mindie-agent-dsh`) to be republished**.

---

## 1. Key Changes

1. **Release Channel Manifest ([`channels/0.1.json`](../../channels/0.1.json), `schema: "mindie-release-channel/1"`) & Decoupled Component Evolution**:
   - Establishes the `track: "0.1"` channel manifest declaring `milestone_version: "0.1.0"`, `current_patch_version: "0.1.0"`, the verified versions/tags/commits of all 12 repositories, and the channel update policy (`independent_update_allowed: true`, `hotfix_trigger_on_error: true`, `etag_poll_interval_sec: 3600`, `background_poll_interval_sec: 86400`);
   - Decouples shared component bugfixes from host plugin releases: throughout the `0.1.x` patch track (`0.1.0` → `0.1.1` → `0.1.2`), single-component patches are published via `channels/0.1.json` without republishing the four host plugins.
2. **Independent Single-Component Updates (`< 500ms` Atomic Idle Switch)**:
   - When only one or a subset of shared components changes in `channels/0.1.json`, the background updater performs an incremental `uv` single-package replacement and switches the canonical binding atomically in `< 500ms` once the service is idle.
3. **Three-Tier Rapid Rollout**:
   - **(a) Fault/Crash-Triggered Immediate Self-Healing Check (`hotfix_trigger_on_error: true`)**: Whenever `diagnostics` or an MCP tool encounters an unexpected runtime failure, the updater immediately bypasses the 24-hour (`86400s`) cooldown to check `channels/0.1.json` for a hotfix targeting the faulting component;
   - **(b) Lightweight HTTP `ETag` Channel Polling (`etag_poll_interval_sec: 3600`)**: Performs a lightweight `If-None-Match` poll against `channels/0.1.json` every hour (`304 Not Modified` fast path with zero payload parsing overhead when unchanged), alongside the `86400s` (`24h`) full background poll interval;
   - **(c) Zero-Code Knowledge & Rule Feed Hot-Reload**: Continuously syncs and hot-reloads `L1–L4` graded knowledge units and triage rules across the 7 public Ascend corpora via `feed_sync` without reinstalling packages or restarting worker processes.
4. **Full `0.0.3` Verified 12-Repository Capability Baseline**:
   - Carries forward the verified `knowledge v0.13.0`, `profiler v0.5.0`, `sim v0.7.0`, `diagnostics v0.5.1`, `coordinator v0.6.2`, `npu-top v0.2.1`, and `remote-dev v0.10.4` releases and benchmarks.

## 3. `0.1.0` → `0.1.1` Single-Component Hotfix Workflow & Benchmark Evidence

- **12-Repository Benchmark & Value Evidence**: See the [`0.0.3` Measured Evidence](0.0.3.en.md#3-component-value-verification--measured-evidence), [`component-value-results.md`](0.0.3/component-value-results.md), and [`benchmark-results.md`](0.0.3/benchmark-results.md).
- **Standard `0.1.0` → `0.1.1` / `0.1.2` Hotfix Workflow**:
  1. Publish a new tagged Release in the modified component repository (e.g., `mindie-agent/diagnostics` or `mindie-agent/remote-dev`) after passing its `mindie-bench` release gates;
  2. Increment `current_patch_version` to `"0.1.1"` in [`channels/0.1.json`](../../channels/0.1.json), update only the patched component's `version`, `tag`, and `commit`/`revision`, and append an entry to `patch_releases`;
  3. Installed host plugins detect the channel update via lightweight HTTP `ETag` polling (`3600s`) or fault-triggered immediate self-healing (`hotfix_trigger_on_error: true`), perform an incremental `uv` single-package update in the background, and cut over atomically in `< 500ms` during an idle window.
