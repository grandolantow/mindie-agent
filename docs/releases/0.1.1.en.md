## 2. Session Usage: Deterministic Tools Ready by Default, Knowledge Enabled Explicitly per Session

In a new session, configured deterministic engineering tools are available by default, including remote development (`remote-dev`), device probing (`npu-top`), resource leases and topology coordination (`coordinator`), performance profiling (`profiler`), simulation calculations (`sim`), and factual status queries (`diagnostics`). Their existing permission and security configurations continue to apply.

Invoke `/mindie-agent` manually in the current session when you want knowledge retrieval or experience reuse (Codex also accepts `$mindie-agent` and its plugin-qualified entry). A single invocation authorizes subsequent turns in the same session until explicit deactivation via `/mindie-agent off`. New chats, forked sessions, and subagents start silent by default and require their own activation.

This session grant covers the entire knowledge loop: retrieval, explanation, feedback, distillation, synchronization, and background experience capture. Public or cross-scope contribution still requires saved contribution consent and an allowed project scope; installing a plugin or enabling contribution consent alone does not activate session knowledge.

Passive sessions receive no knowledge Skill body, onboarding prompt, or unsolicited activation reminder. If the model accidentally invokes a knowledge tool in an inactive session, the runtime rejects the call at the shared Admission gate before starting the knowledge service, reading the local corpus, or capturing conversation material. Ordinary deterministic tools continue to work normally.

## 3. Core Fixes & Engineering Improvements

### 1. Session-Explicit Knowledge Gate, Whole-Delivery Token Budget Estimation & Host Exploration Pass-Through (`knowledge` & Four Host Plugins)

- **Aligned Manual Entry & Shared Admission Gate**: Legacy implicit or automatic associations no longer authorize knowledge access. Fixed post-entry knowledge preparation on Codex and session grant restoration after plugin reload on DSH. Parametrized regressions cover inactive, active, subsequent-turn, new-session isolation, revocation, and background capture paths across all four plugins.
- **Whole-Delivery Token Budget Estimation & Complete Exploration Premises (`knowledge #97` / `#100`)**: `mindie_knowledge/graded/budget.py` uses `response_token_estimate` to enforce unified whole-delivery token budget estimation and budget consistency across the final delivered `query`, `explain`, and `mixed_query` payloads (including `exploration_context` and the `usage` block, with `budget_scope = WHOLE_DELIVERY_SCOPE`, rather than a model-specific exact tokenizer count). When the irreducible protocol envelope estimate exceeds the requested budget, it reports `budget_met=False` and `minimum_tokens`; single-ref `explain` re-evaluates the budget estimate via `reconcile_budget_truth` after merging the legacy view; exploration mode preserves unshortened unit bodies, drops whole units in `L4 -> L2 -> L1` order into `excluded_units` when over budget (listing withheld refs in `subagent_fact_pack.prompt_brief`), and refreshes derived views via `refresh_exploration_mounts`; navigation views strip only preview `excerpt` text (`excerpt_omitted=True`) while keeping material references intact so `related_next` pagination cursors stay reachable.
- **Single-Transaction Deduplicated Delivery Accounting & Mixed-Query Index Binding (`knowledge #97` / `#99`)**: `observe_delivered` records receipts strictly from the final trimmed payload—counting each `(unit_id, revision)` once across results, cards, foundation cards, and `exploration_context.mounted_units` inside a single SQLite write transaction (`_write_txn`); `mixed_query` passes `defer_delivery=True` so budget trimming and delivery receipts use the exact in-memory `RoutingIndex` instance that assembled the graded sub-page even if a concurrent feed installation updates the store; inherited premises are registered as readable rather than independent deliveries.
- **Independent Component Release Discovery & Side-by-Side Runtime Preparation (`knowledge #101`, commits `0e4123d` / `7357417`)**: Adds `component_releases.py`, `component_runtime.py`, `runtime_inventory.py`, and `release_http.py` so host updaters discover formal GitHub Releases directly from official component repositories, verify immutable tag SHAs, `pyproject.toml`, and `benchmark-results.json`, and build locked side-by-side `uv` environments without starting a knowledge worker or altering the manual `/mindie-agent` session activation contract (`1555 passed, 22 skipped, 3 deselected, 3 subtests` full local suite; `58 passed` targeted; 3 CI workflows passed).
- **Pure Exploration Pass-Through Across All Four Host Plugins (Codex `#58`, CC `#43`, Kimi `#46`, DSH `#16`)**: All four host plugins restrict their scope to MCP parameter validation, host identity, and protocol adaptation—passing the knowledge engine's exploration output straight through without re-stripping L3, rebuilding fact packs, or re-normalizing `conditional_avoid`, while preserving the manual `/mindie-agent` session gate.
- **Verified Test Facts**: Combined 8-module knowledge budget, deduplicated delivery, and manual-entry gate suite passed **`105 passed, 1 skipped` in `13.02s`**; targeted regressions across all four host plugins locked against formal `knowledge 0.13.2` passed (`Codex 45 passed + 5 subtests`, `CC 32 passed + 16 subtests`, `Kimi 30 passed + 6 subtests`, `DSH 39 passed + 4 subtests`).

### 2. Remote SSH Cleanup Diagnostics, HBM Telemetry Consistency & Observed-Capacity Placement (`remote-dev 0.10.6` & `coordinator 0.6.3` Candidates)

- **Preserving Primary SSH Exceptions Across Cleanup Failures (`remote-dev #43`)**: In `ssh_stream.py` and `ssh_forward.py` (`LocalForward.__exit__`), when both the primary operation and local cleanup fail, `record_cleanup_failure(primary_error, cleanup_error)` records the cleanup failure on `primary_error.cleanup_error` (and via `add_note`) before re-raising the primary exception (fixing an unbound `transport` `NameError` introduced during module splitting) and removes unreachable duplicate post-exit cleanup branches in attached streams.
- **Dual-Die A3 Physical Unit Counting & Observed Free HBM Normalization (`remote-dev #44`)**: `normalize_remote_probe_spec` counts independently leasable physical execution units (`dies`) for `npu_count` and `free_npus` (each dual-Die Ascend 910C A3 card contributes `2` physical units) and treats `free_phy_ids` (including an empty list `[]`) as authoritative when present. `vram_free_mb` is computed strictly as `hbm_total_mb - hbm_used_mb` across non-busy units with measured usage—never substituting total nameplate HBM for unobserved free capacity—and exposes `vram_free_observed`.
- **Preparation Job Status Refresh, HBM Telemetry Consistency & Host-Capacity Admission (`coordinator #63` / `#64`)**:
  - Restored the missing `preparation_control` import in `service_gang.py` (which previously caused remote preparation job refresh to record an internal `NameError` as `state="uncertain"`) and wired preparation job refresh into status observation and terminal progression.
  - `fleet_probe_parser.py` preserves factual measured `hbm_used_mb` on Ascend 950DT (A5) cards for headroom calculations while continuing to derive A5 busy status from the process table; `parse_npu_smi_usages` applies card-wide `npu-smi info -t usages` figures only to single-Die or card-only rows (with card and physical-Die free/busy lists derived consistently via `device_occupancy_inventory`) so card-wide statistics never overwrite dual-Die A3 telemetry.
  - When a role declares `cpu_cores`, `memory_mb`, or `hbm_mb`, `ServiceEvidenceMixin._observe_host_specs` probes candidate hosts via `_probe_host_record` (`probe_machine_record`) and enforces the resulting `host_specs` snapshot across `CoordinatorService` donor selection (`can_prepare` followed by `hardware_shortfall`), container provisioning (`hardware_shortfall`), post-preparation verification, and final role binding (`runtime_matches`), while `select_runtimes(..., host_specs=...)` also accepts `host_specs`. Unobserved or undersized hosts report deduplicated per-host shortfalls via `shortfall_reason`.
- **Verified Test Facts**: Standing A2 (`173.125.1.2`) and A3 (`192.168.13.165`, `192.168.13.154`) read-only fleet capacity probe (`test_live_fleet_probe_and_capacity_across_a2_and_a3`) passed **`1 passed` in `8.01s`**.

### 3. Cooperative Diagnostic Intake Draining & Profiled Kernel Cost Plans (`diagnostics 0.5.2` & `sim 0.7.1` Candidates)

- **Cooperative Record-Boundary Intake Drain, Offline Stage-Admission Budget & Cursor Preservation (`diagnostics #29`)**:
  - Building on the existing `max_files=256`, `max_bytes=8 MiB`, and `4096` directory-entry per-cycle bounds in `ingest()`, `0.5.2` adds cooperative `cancel` and monotonic `deadline` checks between candidate JSONL files and after each complete JSONL record—setting `counts["limited"] = 1`, stopping at a complete record boundary, and writing the byte `offset` of the last enqueued complete record to the SQLite `cursors` table for the next cycle (without claiming an `exactly-once` guarantee across `SIGKILL` or process crashes).
  - In `run_cycle`, once `cancel` is set, the worker keeps data already collected in the cycle, starts no further root `ingest`, `prune`, or `publish_one` stages, and returns `status="degraded"` and `limited=1`.
  - `reporting maintain --budget-seconds` is strictly an offline maintenance stage (`"network": False`, performing no support-bundle packaging, remote GitHub reconciliation, or `POST` requests); `budget_seconds` (default `75` seconds) serves as a stage-admission budget that reserves `3.0` seconds before each root `ingest` and `prune` for SQLite `Outbox` and `cursors` writes, recording `category="budget_exhausted"` and `status="degraded"` when budget expires (without claiming an OS-level 20-second service stop guarantee or a hard total wall-clock cap).
  - Bounded outbound reconciliation reading is documented separately as an unimplemented design follow-up in `docs/outbound-reconciliation-followup.en.md`, preserving the invariant that `unknown` `POST` outcomes are never replayed and GitHub search misses are never treated as remote absence.
  - **Verification & Honest Boundary**: The local contract suite passed **`132 passed`** on both Python 3.11 and Python 3.13. Note that one earlier Windows legacy consent-isolation test run ingested 1 record when 2 were expected and passed on rerun; its root cause remains undetermined and is not claimed fixed in this patch.
- **Profiled Kernel Cost Plans, Captured Duration Floors & Declared-Work Proxies (`sim #16`)**:
  - `ProfiledKernelProvider` (`mindie_sim/profiled_kernel.py`, `backend="profiled_kernel"`) matches operators against explicit configured `bindings` (requiring `binding["timing_scope"] == "profiled_device_kernel"` plus exact operator identity, `hardware_key`, and `environment_key` agreement) and queries `variants` joined with `costs` in the `mindie-profiler` SQLite store read-only.
  - Emits `ExecutionStage("captured_service", demands=demands, minimum_duration_ms=observation["median_ns"] / 1e6)` so the captured median kernel duration acts as a per-task completion floor while charging the operator's declared `cube`/`vector`/`hbm`/`mte2`/`mte3` work onto shared stage resources (refusing zero-demand operators with `profile_occupancy_undeclared_for_shared_stage`, and recording `independent_accuracy_acceptance=False`).
  - In `a3_cost.py`, dedicated measured calibrations and the communication topology model keep their normal precedence over a `profiled_kernel` plan and record `superseded_profile_variant`, while contradictory declarations (`PROFILE_VARIANT_CONTRADICTIONS`) or unavailable/analytic-substituted `profile_variant` bindings raise `A3InputError`. Operators priced by an observed `profiled_kernel` plan receive `calibration.status = "profiled_kernel_observed"`, and `record_prediction_misses()` in `a3_measurement.py` skips queuing duplicate calibration requests for them.
  - **Verified Test Facts**: Targeted provider test suite passed **`22 passed`**.
