## 2. Session Usage: Deterministic Tools Ready by Default, Knowledge Enabled Explicitly per Session

In a new session, configured deterministic engineering tools are available by default, including remote development (`remote-dev`), device probing (`npu-top`), resource leases and topology coordination (`coordinator`), performance profiling (`profiler`), simulation calculations (`sim`), and factual status queries (`diagnostics`). Their existing permission and security configurations continue to apply.

Invoke `/mindie-agent` manually in the current session when you want knowledge retrieval or experience reuse (Codex supports explicit manual Skill entry such as `$mindie-agent` / `/mindie-agent`, and Claude Code supports the plugin-qualified `/mindie-agent:mindie-agent` entry). A single invocation authorizes subsequent turns in the same session until explicit deactivation via `/mindie-agent off`. New chats, forked sessions, and subagents start silent by default and require their own activation.

This session grant covers the entire knowledge loop: retrieval, explanation, feedback, distillation, synchronization, and background experience capture. Public or cross-scope contribution still requires saved contribution consent and an allowed project scope; installing a plugin or enabling contribution consent alone does not activate session knowledge.

Passive sessions receive no knowledge Skill body, onboarding prompt, or unsolicited activation reminder. If the model accidentally invokes a knowledge tool in an inactive session, the runtime rejects the call at the shared Admission gate before starting the knowledge service, reading the local corpus, or capturing conversation material. Ordinary deterministic tools continue to work normally.

### 3. Cooperative Diagnostic Intake Draining & Profiled Kernel Cost Plans (`diagnostics 0.5.2` & `sim 0.7.1`)

- **Cooperative Record-Boundary Intake Drain, Offline Stage-Admission Budget & Cursor Preservation (`diagnostics #29`)**:
  - Building on the existing `max_files=256`, `max_bytes=8 MiB`, and `4096` directory-entry per-cycle bounds in `ingest()`, `0.5.2` adds cooperative `cancel` and monotonic `deadline` checks between candidate JSONL files and after each complete JSONL record—setting `counts["limited"] = 1`, stopping at a complete record boundary, and writing the byte `offset` of the last enqueued complete record to the SQLite `cursors` table for the next cycle (without claiming an `exactly-once` guarantee across `SIGKILL` or process crashes).
  - In `run_cycle`, once `cancel` is set, the worker keeps data already collected in the cycle, starts no further root `ingest`, `prune`, or `publish_one` stages, and returns `status="degraded"` and `limited=1`.
  - `reporting maintain --budget-seconds` is strictly an offline maintenance stage (`"network": False`, performing no support-bundle packaging, remote GitHub reconciliation, or `POST` requests); `budget_seconds` (default `75` seconds) serves as a stage-admission budget that reserves `3.0` seconds before each root `ingest` and `prune` for SQLite `Outbox` and `cursors` writes, recording `category="budget_exhausted"` and `status="degraded"` when budget expires (without claiming an OS-level 20-second service stop guarantee or a hard total wall-clock cap).
  - Bounded outbound reconciliation reading is documented separately as an unimplemented design follow-up in `docs/outbound-reconciliation-followup.en.md`, preserving the invariant that `unknown` `POST` outcomes are never replayed and GitHub search misses are never treated as remote absence.
  - **Verification & Honest Boundary**: The local contract suite passed **`132 passed`** on both Python 3.11 and Python 3.13. Note that one earlier Windows legacy consent-isolation test run ingested 1 record when 2 were expected and passed on rerun; its root cause remains undetermined and is not claimed fixed in this patch.
- **Profiled Kernel Cost Plans, Captured Duration Floors & Declared-Work Proxies (`sim #16`)**:
  - `ProfiledKernelProvider` (`mindie_sim/profiled_kernel.py`, `backend="profiled_kernel"`) matches operators against explicit configured `bindings` (requiring `binding["timing_scope"] == "profiled_device_kernel"` plus exact operator identity, `hardware_key`, and `environment_key` agreement) and queries `variants` joined with `costs` in the `mindie-profiler` SQLite store read-only.
