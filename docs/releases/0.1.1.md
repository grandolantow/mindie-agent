## 二、会话使用方式：确定性工具默认就绪，知识功能按会话显式启用

在一个新会话中，已配置的确定性工程工具默认可用，包括远端开发（`remote-dev`）、设备探测（`npu-top`）、资源租约与拓扑协调（`coordinator`）、性能分析（`profiler`）、仿真计算（`sim`）和事实状态查询（`diagnostics`）。它们继续遵守各自的权限与安全配置。

需要知识检索或经验复用时，在当前会话手动输入 `/mindie-agent`（Codex 支持显式手动 Skill 入口如 `$mindie-agent` / `/mindie-agent`，Claude Code 支持 `/mindie-agent:mindie-agent` 带插件命名空间入口）。启用一次后，同一会话的后续轮次会沿用该授权，直到显式执行 `/mindie-agent off` 停用。新会话、分支会话（Fork）和子代理（Subagent）均保持默认静默，需要各自显式启用。

这项会话授权覆盖整个知识闭环：检索、解释、反馈、蒸馏、同步，以及后台经验采集。公开或跨范围经验贡献仍需满足已保存的贡献同意与项目范围配置；安装插件或开启贡献同意本身不会自动启用会话知识功能。

未启用的会话不会收到知识 Skill 正文、知识引导或缺少授权的主动提醒。如果模型在未启用会话中意外调用了知识工具，运行时会在启动知识服务、读取本地语料或采集对话内容前直接在共享 Admission 门禁拒绝调用；普通确定性工具照常工作。

### 2. 远端 SSH 清理诊断保留、HBM 遥测一致性与实测容量准入（`remote-dev 0.10.6` & `coordinator 0.6.3`）

- **SSH 流式与转发清理错误不掩盖主异常（`remote-dev #43`）**：`ssh_stream.py` 与 `ssh_forward.py`（`LocalForward.__exit__`）在主操作已抛出异常且本地清理也失败时，通过 `record_cleanup_failure(primary_error, cleanup_error)` 将清理失败记录到主异常的 `cleanup_error` 字段与异常附注中并重新抛出主异常（修复模块拆分后误用未绑定 `transport` 导致 `NameError` 覆盖主错误的问题），同时移除流式命令确认子进程退出（`EXIT:`）后不可达的重复清理分支。
- **A3 双 Die 物理单元计数、实测空闲 HBM 归一化与零权重控制面（`remote-dev #44`）**：`normalize_remote_probe_spec` 按可独立租约的物理执行单元（`dies`）统计 `npu_count` 与 `free_npus`（单张 Ascend 910C A3 双 Die 卡计为 `2` 个物理单元），在存在 `free_phy_ids` 时（含空列表 `[]`）以其为权威空闲物理单元集合；`vram_free_mb` 严格按非繁忙物理单元实测 `hbm_total_mb - hbm_used_mb` 计算（固件/驱动基线占用保持实测值，绝不统一清零或硬扣 `2–3 GiB` 固定常数，未观测到已用显存时也绝不将标称总容量冒充为空闲显存），并显式返回 `vram_free_observed`。高 CPU/内存控制面仅检查元数据（如 `config.json` / `safetensors` 头部与主机规格），绝不加载模型权重或初始化 `torch_npu`/CANN 设备上下文。
