资源引擎替换后，完整与增量输出接口各通过 22 个独立算术、守恒及 reservation 检查，公开时间线回归的 23 个断言也已重新通过，包括跨 DP 不插入额外轮次屏障、链路容量动态回收、未来请求到达前的后台服务、请求归属，以及 forward/sample 消费依赖。容量不足的 reservation 会排队；固定份额与最低份额是两个不同的分配模式，资源占用持续至所属任务完成。

## 10. 当前补测与校准的验收条件

首批真实数据已采集，不等于新曲线入口已经通过验收。独立合成反例发现：同一物理 shape 可因模型或层来源不同被分到 train/heldout；同一 x 的样本先合并会让 heldout 改变训练拟合；重复 measurement/trial 会增加样本数；正确性失败样本曾进入拟合。这些问题已交回实现任务修复。留出数据尚未用于调参，待公开适配入口贯通后再独立评分。

补测清单默认必须完整保存物理条件及来源，或提供经验证的确定性恢复和指定条件导出入口。缩略展示可以只保留部分例子，但完整 shape、precision、recipe、protocol 及未测原因仍须能恢复为具体采集请求。不能仅用“条件数”和少量样例代表其余缺口。

原生算子最小 pilot 先检查正确性和计时协议，再扩展 shape 扫描。输入构造、拼接、CPU reference 和状态恢复不得混入声明为 kernel-only 的计时区间；原生返回新输出的 API 如实记录分配行为，不额外插入 copy 后宣称预分配计时。采样内 30 次 event 是一个 trial 的重复记录，不当作 30 个独立运行。

通信实际展开的首次 Phy 0/1 profiler pilot 因 `latest_start` 到期未获得设备，终态为 `expired`，`granted_devices=[]`；没有启动 profiling 或 NPU 负载。该记录保留，后续仅通过同一共享队列选择可用设备重采。当前通信曲线的 dtype/hardware/CV 条件隔离和多终端完成 join 已通过对应反例；物理 AIV 占用、未测 payload 的阶段工作推导，以及 route/core/timing scope 的分组仍在修复与复验。
